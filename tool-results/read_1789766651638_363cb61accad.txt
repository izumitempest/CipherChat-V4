     1→# CipherChat — Complete Change Record
     2→
     3→A detailed, chronological record of every change and addition made to the
     4→project, cross-referenced against the internal task IDs used in
     5→`worklog.md`. Final state at time of writing: **124/124 property tests
     6→green, lint clean, tsc clean, all services healthy.**
     7→
     8→**What the product is:** an end-to-end-encrypted, ephemeral group chat.
     9→All cryptography runs in the browser; the server is a blind relay that
    10→stores no messages; rooms die on a clock (or by fire); the only identity
    11→is a per-room deterministic alias in a muted ink colour. Single
    12→user-visible route (`/`), hash-routed client-side. Aesthetic: warm
    13→paper, ink, and forest — deliberately *not* cyber/hacker.

    17→## 1. Foundation (Tasks 0–8)
    18→
    19→### 1.1 Architecture decisions (Task 0)
    20→
    21→- **One route, hash router**: `/` with `#/`, `#/new`, `#/join/:id`,
    22→  `#/rooms`, `#/r/:id`. Invite links use `/?join=<roomId>`.
    23→- **Crypto in the browser**: room key derived from the room password;
    24→  AES-GCM message encryption; per-device signing keys; forged messages
    25→  (bad signature) are quietly rejected.
    26→- **Server is a blind relay**: REST for room lifecycle + member
    27→  registry (keyed by pubkey), socket.io mini-service `:3003` for
    28→  in-memory presence and message relay. **No message persistence —
    29→  new joiners see no history, by design.**
    30→- **Refresh = keys wiped** (memory only) → rooms lock; the room list
    31→  survives in localStorage; locked rooms unlock by re-entering the
    32→  password.
    33→- **Identity**: deterministic alias (adjective + animal, e.g. "Quiet
    34→  Heron") + one of 8 curated muted ink colours, derived from the
    35→  fingerprint of the member's signing pubkey. No red/terracotta hues
    36→  (terracotta is reserved for impermanence/destruction).

   222→## 3. Protocol v2 — the security hardening pass (Task 19)
   223→
   224→The largest single change to the codebase, driven by an external
   225→acceptance review. **All six property suites were written RED first.**
   226→
   227→- **Replay defense (P0)** — `lib/protocol.ts`: per-(sender, session)
   228→  monotonic counters, ±10-minute timestamp window, frame-id dedup,
   229→  FIFO cap; receive pipeline order fixed as shape → registry eviction
   230→  → key version → signature → replay → dispatch. Watermarks persist
   231→  per room per device (survive refresh).
   232→- **Uniform padding (P1)**: every control frame is JSON → ECDSA sign
   233→  → pad → AES-256-GCM at a uniform **20480+16 bytes** (20480 chosen
   234→  because the 4000-char worst-case UTF-8 message cannot fit the
   235→  spec's 4096 — uniformity is the property). File transfers: payload
   236→  padded to a fixed 2.8 M base64 chars, always **exactly 45 uniform
   237→  frames** (1 meta + 44 chunks) regardless of true size — the relay
   238→  cannot distinguish typing from messages or read file sizes.
   239→  **Typing became an encrypted uniform frame.**
   240→- **KDF upgrade (P1)** — `lib/kdf.ts`: PBKDF2 → **argon2id**
   241→  (m=64 MB, t=3, p=1, hash-wasm) with random 16-byte salt in a
   242→  **versioned bundle** `{v:2,…}`; legacy PBKDF2 rooms still unlock.
   243→- **Per-room identity (P1)** — `lib/room-identity.ts`: one device
   244→  seed; per-room ECDSA keypair = HKDF(seed, roomId) — same device,
   245→  two rooms ⇒ different pubkeys and aliases (registries cannot be
   246→  correlated). Old global device key retired.
   247→- **Real key rotation on leave (P0)** — `lib/room-protocol.ts`
   248→  `RoomCipher`: the coordinator (lowest memberId among connected)
   249→  generates a **random** 256-bit key (never password-derived),
   250→  delivers it pairwise over authenticated ECDH, signed, sealed under
   251→  the entry key — every member can read the offer, only the
   252→  recipient can unwrap the key. The **server epoch is the rotation
   253→  ledger** (persisted): post-refresh rotations re-seal past any key
   254→  a departed member held; key requests self-heal through
   255→  version-randomized fallback rotations that converge monotonically.
   256→- **Relay/API hardening (P2)** — `lib/rate-limit.ts`: token bucket
   257→  per socket, IP limit on room creation.
   258→- **Adversarial review (subagent, read-only)** found and the round
   259→  fixed: unauthenticated relay joins (registry poisoning → REST-
   260→  authoritative writes), unauthenticated leave, a legacy spoiler
   261→  frame, v1 downgrade in v2 rooms, missing key-request sender, kv
   262→  saturation brick (KVERSION_CAP 1e6), unbounded maps (capped).
   263→- Test count: **47/47**. Test count milestone: first 92-test run
   264→  came later. Browser E2E covered rotation, rejoin key delivery,
   265→  file transfer through 45 uniform frames with sha-verified
   266→  assembly, and refresh-lock + argon2id unlock.
   267→- `README.md` created, including the honest **"What CipherChat does
   268→  NOT protect against"** section; DESIGN.md gained §6 threat model.

   459→## 10. Task 26 — the password breach (user challenge)
   460→
   461→User pasted the live DOM of the create-sheet password input
   462→(`type="text"`, `value="quill-grove-harbor-orchard"`) and asked to
   463→find the breach. Three layers found and fixed:
   464→
   465→1. **CRITICAL — the generator drew from `Math.random()`** (V8
   466→   xorshift128+, predictable). `lib/identity.ts` rewritten: a
   467→   **256-word list** in the app's stationery/nature voice, sampled
   468→   via `crypto.getRandomValues` with rejection-guarded unbiased
   469→   sampling (one byte = one word at list size 256, zero modulo
   470→   bias; duplicates skipped).
   471→2. **CRITICAL — 18 bits of keyspace** (24 words, 4 picks). Raised to
   472→   **5 words = 2^40 candidates** — the public verifier oracle moves
   473→   from an afternoon to a multi-year grind through argon2id.
   474→3. **Input hygiene**: `autocomplete="off"` → `"new-password"` (the
   475→   documented suppressor of Chrome's save-password prompt for
   476→   ephemeral room passwords); the reveal toggle became
   477→   keyboard-focusable with `aria-pressed`; plaintext state now
   478→   clears the moment its job is done (create sheet, join, unlock,
   479→   invite). The memory-only session retention stays, documented and
   480→   deliberate (the invite sheet re-shares the password; legacy v1
   481→   epoch re-derivation needs it).
   482→- DESIGN.md gained the "Room passwords" bullet stating all of this,
   483→  including the inherent limit.

   487→## 11. Task 27 — the DevTools value-attribute fix (user challenge)
   488→
   489→User: *"while typing using DevTools, in sensitive fields like
   490→passwords, the `value=""` tag always reveals it. Can't that be
   491→hidden or removed?"*
   492→
   493→- **Diagnosis**: React controlled inputs mirror every keystroke into
   494→  the DOM `value` **attribute** (visible in Elements), and the
   495→  plaintext also sat in React state (readable in React DevTools).
   496→- **Fix — `PasswordField` became the uncontrolled secret field**:
   497→  props now `Omit<InputHTMLAttributes, "value" | "defaultValue">` —
   498→  a **compile error** to pass either. The attribute is never
   499→  written; no plaintext ever sits in React state. Parents
   500→  seed/wipe imperatively through the forwarded ref (`el.value = …`
   501→  sets the property only) and read once at submit.
   502→- **All four consumers migrated**: create sheet (landing), join form
   503→  (invite), locked-room view (chat), unlock sheet (room-list) — each
   504→  reads the ref at submit and wipes on success/close/unmount.
   505→- **Subtle bug found during QA and fixed**: the create-sheet seed
   506→  effect initially lived on the parent — but Radix `Presence` mounts
   507→  portal children in a **later commit** than the parent's open-state
   508→  change, so it fired before the input existed. Fix: `SeedPassphrase`,
   509→  a render-null component *inside* the portal content whose mount
   510→  effect seeds the field exactly when it comes to life (and re-runs
   511→  on every reopen).
   512→- **Unrelated real bug found & fixed — the permanent offline state**
   513→  visible in the user's screenshot: `.env` was missing
   514→  `NEXT_PUBLIC_RELAY_URL`, so clients fell back to `/relay/`, which
   515→  the sandbox gateway does not forward → every room showed "The
   516→  line is down" forever. `.env` now carries the sandbox value
   517→  `/?XTransformPort=3003`; verified live (composer enables,
   518→  messages relay end-to-end).
   519→- Verified: `getAttribute('value') === null` at every step of every
   520→  flow — seeded, toggled, typed-into, reseeded, submitted, unlocked.
   521→  The honest limit stands in DESIGN.md: the DOM `value` *property*
   522→  is always readable from the user's own machine — that is true of
   523→  every site, and the page must read the secret to encrypt with it.

   527→## 12. Round 29 — quoted replies + in-app media viewers
   528→
   529→Two features landed together because they touch the same seam: what
   530→a message can point at, and what opening a message means.
   531→
   532→### 12.1 Quoted replies to specific messages
   533→
   534→- **`src/lib/types.ts`** — new `ReplySnapshot` interface
   535→  `{id, senderId, snippet, file?}`; `REPLY_SNIPPET_MAX = 120`;
   536→  `makeReplySnapshot()` builds the quote at reply-compose time — **view-once
   537→targets are quoted as "Sealed message"**, never by their contents (the
   538→sealed card's own rule: nothing shows before opening); file targets quote
   539→the file's name and carry `file: true`; text targets are
   540→whitespace-collapsed and capped at the first 120 characters.
   541→  `sanitizeReplySnapshot()` is the post-verification UI gate (id/senderId
   542→capped at 64 chars, snippet at 160, malformed shapes dropped — a failing
   543→snapshot renders the message unquoted, never broken);
   544→  `isReplySnapshot()` is the shape guard used on both sealing and
   545→verification. `MessageView` gained `replyTo?: ReplySnapshot`.
   546→- **`src/lib/protocol.ts`** — `FrameBody.reply?: ReplySnapshot`; new exported
   547→  `replyCanonical()` serialises the snapshot deterministically
   548→  (unit-separator-joined slots — the separator is cosmetic, slot order is
   549→  what binds); **`canonicalV2` now appends the replyCanonical component as a
   550→  12th field** — the quote is signature-covered, so a quote is exactly as
   551→  unforgeable as the words it carries; a tampered quote breaks the ECDSA
   552→  signature. `sealFrame` extracts and includes it.
   553→- **`src/lib/room-protocol.ts`** — `sealText`/`sealFile` accept `reply`; the
   554→  file-assembly map stores it; the completed-file OpenResult carries it;
   555→  and `open()` verifies with the **raw** reply before any sanitising —
   556→  verification must recompute the sender's exact canonical string, not a
   557→  cleaned-up one.
   558→- **`src/store/app.ts`** — `sendMessage(text, file?, ttlOverride?, reply?)`;
   559→  the optimistic view carries `replyTo`; both receive paths (text frames and
   560→  file-assembly completion) sanitise for the view, after verification.
   561→- **UI, `src/components/cc/bubble.tsx`** — `QuoteBlock`: ink-coloured left
   562→  border in the **quoted** sender's ink (`var(--ink-N)`, "Someone" in mute
   563→  once they leave), alias + snippet, a `FileText` glyph for file quotes;
   564→  click → jump to the original (`scrollIntoView` center) with a
   565→  `quote-flash` soft forest pulse in `globals.css` (1300ms, once;
   566→  reduced-motion: static 8% tint); the honest toast "That message is no
   567→  longer in this session" when the original burned or expired. Reply
   568→  affordances, three roads to one verb: the context menu's "Reply" item
   569→  (press-and-hold on touch), a hover-only reply icon button beside the
   570→  bubble on desktop (`group/row` opacity transition, `-left-10` for self /

   573→- **UI, `src/components/cc/composer.tsx`** — the reply slip above the input
   574→  (quote + X to cancel); the input is focused when a reply begins (touch
   575→  included — the reply IS an intent to write); submit seals the snapshot
   576→  into the message; **Escape while replying cancels the quote first**, with

   589→### 12.2 In-app viewers for ALL media (no forced downloads)
   590→
   591→- **`src/components/cc/file-viewer.tsx` REWRITTEN** — exported

   593→  image | video | audio | pdf | text | csv | binary. All bytes decode once
   594→  to memory and render through **revocable blob: URLs** — created in an
   595→  effect keyed on the message id, revoked on switch/unmount. Nothing is
